# New Mexico

183 cameras from NMRoads (NMDOT), snapshot-only, built by `builders/build-states-nm.py`.
New Mexico is the one state whose images go through a proxy, and the reason is in
the data rules.

## Where the list comes from

Two JSONP feeds joined by name. `servicev5.nmroads.com/RealMapWAR/GetCameraInfo` returns
one row per camera with coordinates, title, a `snapshotFile` URL, and a `cameraType`
(iDome, Pelco Spectra, blank, RWIS2). `servicev4admin.nmroads.com/RealMapWAR/GetCachedObject?key=RWISData`
returns road-weather text per station. The builder adds a callback name and strips the
wrapper. Read 2026-07-10.

## How images and video are read

The snapshot host, `ss.nmroads.com`, is http-only: port 443 refuses the connection. Ora is
served over https, so the browser blocks the image as mixed content. The honest http URL
is kept in the data anyway, because the sweep must fingerprint the real bytes off the
origin and the health file must key on the same string. The state's index entry carries
`imgproxy: "wsrv"`, and `index.html` rewrites the image through `https://wsrv.nl/?url=`
only at render time, with the cache-buster inside the proxied URL so the proxy refetches
the origin. Video is RTMP, which no browser plays, so it is ignored.

## What a camera gives us

Name, one view. The 9 RWIS2 rows are weather stations with a camera; 8 of them match a
weather text by name, shown as a chip (temperature, humidity, pressure, wind; some read
n/a, kept as-is).

## Known limits

- Dependent on the wsrv.nl proxy for display. The data does not depend on it.

## Runbook

From the repo root:

```bash
python3 builders/build-states-nm.py
```

Expected: 183 cameras, `video: false`, `imgproxy: wsrv` in the index.
