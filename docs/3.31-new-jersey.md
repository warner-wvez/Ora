# New Jersey

808 cameras from 511nj.org, NJDOT's and the NJ Turnpike Authority's shared site. All
video, no still images, played through the [stream relay](1.4-stream-relay.md).
[Decision 0016](6-decisions/0016-new-jersey-through-the-relay.md), which supersedes the
2026-07-12 verdict that left the state off the map ([0004](6-decisions/0004-new-jersey-skipped.md)).
Traced 2026-10-22 from a HAR of 511nj.org/camera.

## Where the list comes from

511nj.org's own page does three things before it lists a camera, and the builder does the
same:

1. A silent guest login, `POST /account/login` with
   `{"username": "public", "password": "", "role": "public"}`. Nobody types anything. The
   answer is a Keycloak bearer token good for six minutes, sent back in a `Token` header.
2. `POST /client/trafficMap/getTourList`: 85 road "tours".
3. `POST /client/trafficMap/getCameraDataByTourId` with `{"tourId": N}` for each tour. No
   single call lists every camera, so the builder reads all 85 and merges by camera id.
   Tours are loose: each also sweeps in cameras on crossing roads, so a tour does not say
   which road a camera watches.

The page AES-encrypts each request body (CBC, a fixed key and IV in its public
`main-*.js`) and sends `{"encryptedData": "<hex>"}`. Python's standard library has no AES,
so the builder shells out to `openssl`. The Azure firewall in front of 511nj.org refuses a
desktop-browser `User-Agent` sent without the rest of a browser's headers, so the builder
sends a plain request.

## How images and video are read

Video only. Every camera is HLS on one of two hosts, and both answer CORS to 511nj.org
alone:

| Host | Cameras | Lock today |
|---|---|---|
| `nj-511.wink.co` (NJDOT) | 663 | CORS only. In July every playlist needed a five-minute `?otp=` code from `getHlsToken`; on 2026-10-22 the playlist and segments played without one. |
| `njtpk-wink.xcmdata.org` (Turnpike and Parkway) | 131 | CORS, plus a 403 unless the request carries 511nj.org's `Referer`. No code. |

The relay path is the upstream path behind a host key: `relay.wvez.org/nj/w/<path>` for
wink.co and `/nj/t/<path>` for the Turnpike. The stored URL stays the agency's, and
`videoFor()` in `index.html` rewrites it at play time.

wink.co serves low-latency HLS, a quarter-second part per request. The relay drops the
part tags so the player takes plain two-second segments. The Turnpike reuses five segment
names in a loop (`_nj0.ts` to `_nj4.ts`), so the relay sends every New Jersey segment with
`Cache-Control: no-store`.

## What a camera gives us

A name ("NJ-21 @ Murray Street", or a milepost on the Turnpike and Parkway: "MM 104.5
South of Interchange 14"), coordinates, and one stream. The road comes from the name when
it leads with one (`I-`, `US-`, `NJ-`, `CR-`, or the text before " @ "). The 131 milepost
cameras share one host for the Turnpike and the Parkway and name no road, so their road
is blank rather than guessed.

## Known limits

- 14 cameras NJ marks stopped point at a literal `Camera-Unavailable.png`; they are
  location-only pins.
- A handful of streams 404 at any moment (three of seven in the HAR); the popup shows
  NOT LIVE like any dead stream.
- If wink.co starts checking its code again, every NJDOT stream fails until the relay
  learns to fetch a code when a camera opens (`POST /client/trafficMap/getHlsToken` with
  the encrypted camera id, the call 511nj.org's page makes).
- No health sweep: it fingerprints still images and New Jersey has none, the same as West
  Virginia.

## Runbook

```bash
python3 builders/build-states-nj.py    # writes states/NJ.json and the NJ index entry
```

It runs in the Monday rebuild. If the login stops answering, 511nj.org has probably
changed its key: open 511nj.org/camera with devtools, find `etH(` in `main-*.js`, and copy
the new key and IV.
