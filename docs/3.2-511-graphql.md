# The 511 GraphQL feed

Seven states run the newer Castle Rock "511" platform, which exposes a GraphQL API instead
of DataTables: Minnesota, Colorado, Iowa, Nebraska, Indiana, Kansas, and Massachusetts,
about 5,400 cameras. Video plays in Minnesota, Colorado, and Iowa.

## Where the list comes from

`POST https://<host>/api/graphql` with `listCameraViewsQuery`, which returns every camera
view with its parent collection's bounding box, snapshot URL, and HLS sources in one
response. Hosts: `511mn.org`, `maps.cotrip.org`, `www.511ia.org`, `www.511.nebraska.gov`,
`511in.org`, `www.kandrive.gov`, `mass511.com`.

## How images and video are read

The snapshot is the view's `url`. Video is the first HLS source. The builder samples up to
eight streams and refuses any URL carrying `token=`.

## What a camera gives us

Name, views grouped by the parent collection, the route designator as the roadway, the
view category as the label.

## Known limits

- Kansas and Massachusetts hand out stream URLs with a signed JWT that expires in 300
  seconds. The stream plays at build time and is dead five minutes after the file is
  written; Kansas shipped a red LIVE badge over 184 permanently-401 cameras until
  2026-07-09. Both are snapshot states now. [Decision 0002](6-decisions/0002-no-expiring-tokens.md).
- Kansas City is bi-state. Missouri's feed also carries the Kansas-side metro cameras;
  the [Missouri](3.14-missouri.md) builder drops them so they are not pinned twice.
- Kentucky's feed lists nine Indiana-side cameras around Louisville that are dead from
  every door; Indiana's layer here carries them live, so Kentucky drops them.

## Runbook

From the repo root:

```bash
python3 builders/build-states-graphql.py     # all seven states
```
