# Texas

3,426 cameras from the MapLarge table behind drivetexas.org (TxDOT), live video and no
snapshots, built by `builders/build-states-tx.py`. Texas was the first video-only state
and the one whose first investigation went down a dead end;
[decision 0005](6-decisions/0005-texas-reads-maplarge-directly.md) records the
correction.

## Where the list comes from

The MapLarge API at `dtx-e-cdn.maplarge.com`, with a Referer of drivetexas.org. The table
id rotates, so the builder resolves it fresh on every run, then pages the full table with
`start` and `take`. Read 2026-07-09.

## How images and video are read

Video-only: `imageurl` is a `https://localhost/thumbs/...` placeholder, so every direction
gets `snapshot: null` and the popup fades the stream in over a dark backdrop. Streams are
SkyVDN HLS with `Access-Control-Allow-Origin: *` on playlist and segments. Because there is
no poster, a stream that never starts must be caught: `index.html` runs a 12-second
watchdog, since a dead SkyVDN stream hangs and hls.js never fires a fatal error. About 93
percent of streams are healthy at a time, about 5 percent persistently dead.

Since September 2026 the stream also needs a token, and the map mints it in the browser.
The state is flagged `"sign": "tx"` in `states/index.json`; `resolveVideo()` in `index.html`
appends `?token=` at play time. No relay: unlike Florida, TxDOT asks for nothing a page on
another origin cannot send, and both the token API and the stream answer
`Access-Control-Allow-Origin: *`.
[Decision 0014](6-decisions/0014-texas-signs-its-own-streams.md) records why, and the
measurements behind the numbers below.

The token is a JWT carrying only `iat` and `exp`, 300 seconds apart. It is not minted on
demand: it is a stored column on the MapLarge table, regenerated when TxDOT rebuilds the
table about every 300 seconds. Three measured facts drive the code:

- **One token opens every camera.** A token read from a camera on `s69` plays a camera on
  `s70`, so the whole state needs one token, not a mint per camera.
- **The freshest token is in the last row.** Token age falls monotonically down the table,
  so signing costs two small requests (about 900 bytes) instead of the 738 KB full table.
- **There is a gap with no valid token at all.** The currently active version keeps serving
  its token past `exp`, so for roughly 19 seconds in every 300-second cycle nothing works.
  An expired token is a hard 401, and a playing stream dies with it, measured 18 seconds
  past `exp`. drivetexas.org has the same gap.

So a Texas player rewrites the token on every hls.js request rather than only at load,
keeps it as fresh as the table allows, and rides out the gap for 70 seconds before it calls
a camera dead. Without that, a Texas stream would play for a few minutes and then be
mislabelled NOT LIVE every cycle.

## What a camera gives us

Name, description, route, jurisdiction, direction, one stream.

## Known limits

- **A stream answers 401 without a token**, and a Referer does not help. That is the lock
  Tennessee and South Carolina lack on the same skyvdn platform. Traced and solved
  2026-09-22: see How images and video are read, above.
- **Texas is dark for about 19 seconds in every 300**, when TxDOT's active table is still
  handing out a token that has already expired. Nothing can be done from this side; the
  player waits it out rather than reporting the camera dead.
- The token lives in the index entry as `"sign": "tx"`, which is a decision rather than
  anything the feed reports. `build-states-tx.py` writes it on every run, and
  `build-states.py` carries `relay` and `sign` across a rebuild, or a rebuilt state would
  silently go dark.
- The geometry lives in the `XY` column as WKT (`POINT (lng lat)`), but only if `XY` is
  named in `sqlselect`. Omit it and the response has no coordinates at all (`allGeo` is
  always empty).
- The API answers any malformed or unrecognised query with a bare HTTP 500 and a generic
  HTML page, so an unknown key, a bad `where`, and a real server fault are
  indistinguishable. Change one variable at a time. The old belief that statewide queries
  500 was a `where` clause that never parsed; there is no area limit.
- TxDOT publishes a single 320x240 or 352x240 rendition per camera, which matters for
  the [vehicle-detection research](5-research.md): about 90 percent of Texas cameras are
  below the resolution a detector needs.
- No health file; video-only.

## Runbook

From the repo root:

```bash
python3 builders/build-states-tx.py
```

Expected: about 3,430 cameras, `video: true`.
