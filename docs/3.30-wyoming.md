# Wyoming

228 sites with 757 views from WYDOT's 511 map (map.wyoroad.info), snapshot-only, built by
`builders/build-states-wy.py`. The one feed that had to be decoded rather than parsed.

## Where the list comes from

The map is an ArcGIS-on-SvelteKit app that fetches its webcam layer as a Protocol Buffers
blob, `https://map.wyoroad.info/wti511map-data/Msg-FFBK373B.pbf`, a
`webcameras_v1_pkg.WebCamerasFeed`: repeated `Xyz { id=1, name=2, images=3 (repeated
Image { id, title, url, sort }), lon=8, lat=9 }`. The builder walks the fields with a tiny
hand-written parser. Every string field is base64 of bytes XOR'd with an ASCII key lifted
from the map bundle; the decode is symmetric. Read 2026-07-11.

## How images and video are read

Images are `https://www.wyoroad.info/web-cam/cache?ref=<blob>`. The `ref` is a stable
handle (a week-old one still resolves), the host is https and serves a normal JPEG, so no
proxy. No HLS is exposed anywhere the browser can play.

## What a camera gives us

Site name, a view per lens with its title.

## Known limits

- The camera's identity is in the query string, not the path. The old health key
  (`split('?')[0]`) would have collapsed all 757 views to one; `snapKey` and the sweep now
  strip only bare-digit cache-busters and keep named parameters, verified byte-identical
  across the other 27 query-bearing states.
- The `Msg-*.pbf` filename is content-addressed. If it rotates, read layer `webcameras`'s
  `geometryURL` from the running map and update the builder.

## Runbook

From the repo root:

```bash
python3 builders/build-states-wy.py
```

Expected: 228 sites, `video: false`.
