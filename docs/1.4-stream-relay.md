# The stream relay

Ora is a static site, and for most states that is enough: the browser fetches the agency's
stream directly. Florida stopped allowing that in September 2026, and Pennsylvania the
same month. Their stream hosts answer only requests that carry the agency's own `Referer`
plus a per-camera token minted through the agency's site, and a browser page on any other
origin cannot send that header however it tries. So the map asks a relay instead: a small
service on the VPS that fetches the stream wearing the agency's headers and passes the
bytes on. [Decision 0013](6-decisions/0013-relay-for-locked-streams.md).

Two states run through it today, Florida on divas.cloud and Pennsylvania on
arcadis-ivds.com. They are the same vendor platform, so the token dance is the same two
calls, and each host rejects the other's `Referer`.

## How a click plays

1. The visitor clicks a Florida pin. `states/index.json` flags Florida with
   `"relay": "https://relay.wvez.org/fl"`, so `videoFor()` in `index.html` rewrites the
   stored stream URL `https://dis-se7.divas.cloud:8200/chan-3936_h/index.m3u8` to
   `https://relay.wvez.org/fl/691/se7/chan-3936_h/index.m3u8`. The `691` is fl511's
   camera id, read from the snapshot URL beside the stream. The stored URL never changes;
   this is the same play-time seam the New Mexico image proxy uses. Pennsylvania is the
   same line with `pa` and `pa-se1.arcadis-ivds.com`.
2. The relay mints a token for camera 691 if it has none cached: the three steps fl511's
   own page performs, anonymously. `GET fl511.com/cctv` once for a session cookie and an
   anti-forgery token; `GET fl511.com/Camera/GetVideoUrl?imageId=691` for the source id;
   `POST divas.cloud/VDS-API/SecureTokenUri/GetSecureTokenUriBySourceId` for the token.
3. The relay fetches the playlist from divas.cloud with `Referer: https://fl511.com/` and
   the token, strips the token from every segment line so the browser asks the relay for
   those too, and returns it with `Access-Control-Allow-Origin` set.
4. hls.js loads the variant playlist, the init segment, and each media segment through the
   same path. The popup's LIVE badge and the is-it-moving check work unchanged.

If the relay is down, hls.js fails fast and the popup falls back to the snapshot with NOT
LIVE, exactly as a dead stream does today.

## What was measured

- Tokens are per camera and were stable across callers and across hours in testing; a
  token minted on a laptop played from the VPS, so they are not bound to an address. The
  relay caches each for up to 12 hours and re-mints once on a 401.
- Both sites rate-limit the token step: fl511 with a 429 after four quick calls, 511pa
  after two or three. Minting is lazy, one camera at a time as visitors click, and a 429
  becomes a 503 with `Retry-After: 15`. The backoff is per state, so one agency's limit
  does not stall the other.
- Pennsylvania needs no session in front of the token step, which Florida does. Its
  `GetVideoUrl` answers a plain anonymous GET, with no cookie and no anti-forgery token.
- A Pennsylvania token opens only Pennsylvania: fl511's `Referer` on an arcadis stream is
  a 401, and the reverse holds. Either `Referer` or `Origin` alone satisfies both hosts.
- A 267 KB segment passed through the relay in 0.6 seconds from a laptop. A stream is
  about 1 Mbps, so ten concurrent viewers are about 10 Mbps through the VPS.
- Cloudflare Workers were tried first and cannot reach the host's port 8200 (522 at the
  edge), which is why the relay lives on the VPS.

## Running it

Locally, from the repo root:

```bash
node --test relay/relay.test.js
cd relay && PORT=8791 node server.js
curl http://127.0.0.1:8791/healthz
curl http://127.0.0.1:8791/fl/691/se7/chan-3936_h/index.m3u8
curl http://127.0.0.1:8791/pa/4774/se1/chan-2274/index.m3u8
```

To test the map against a local relay, open `http://localhost:8934/`, load the state, and
in the console run `LAYERS['st-FL'].relay='http://127.0.0.1:8791/fl'` (or `st-PA` and
`/pa`) before clicking a pin. Open it as `localhost`, not `127.0.0.1`: the default
`ALLOWED_ORIGINS` lists the first and the relay answers the second with a 403.

On the VPS, as a container on the Coolify network so its Traefik proxy terminates TLS:

```bash
scp relay/relay.js relay/server.js relay/Dockerfile root@<vps>:/opt/ora-relay/
ssh root@<vps> 'cd /opt/ora-relay && docker build -t ora-relay:latest . && docker rm -f ora-relay; \
  docker run -d --name ora-relay --restart unless-stopped --network coolify -p 127.0.0.1:8791:8791 \
    -e ALLOWED_ORIGINS="https://warner-wvez.github.io,http://localhost:*" --memory 256m \
    --label traefik.enable=true \
    --label "traefik.http.routers.ora-relay.rule=Host(\`relay.wvez.org\`)" \
    --label traefik.http.routers.ora-relay.entrypoints=https \
    --label traefik.http.routers.ora-relay.tls=true \
    --label traefik.http.routers.ora-relay.tls.certresolver=letsencrypt \
    --label "traefik.http.routers.ora-relay-http.rule=Host(\`relay.wvez.org\`)" \
    --label traefik.http.routers.ora-relay-http.entrypoints=http \
    --label traefik.http.routers.ora-relay-http.middlewares=redirect-to-https \
    --label traefik.http.services.ora-relay.loadbalancer.server.port=8791 \
    ora-relay:latest'
```

`relay.wvez.org` is an A record to the VPS. Traefik orders the Let's Encrypt certificate
the moment it first sees the container's labels, and if the DNS record does not exist yet
that order fails and is never retried: a `docker restart` re-emits the same configuration
and Traefik ignores it. Recreate the container (`docker rm -f` then the `docker run`
above) after the record resolves and the order runs again; the certificate showed up in
`/data/coolify/proxy/acme.json` within a minute. `GET /healthz` reports how many camera
tokens are cached across both states and how old the fl511 session is; Traefik returns 503 for the first
minute after a recreate while the container's health check has not yet passed.

| Variable | Default | Meaning |
|---|---|---|
| `PORT` | 8791 | Listen port inside the container |
| `ALLOWED_ORIGINS` | the map and localhost | Comma list; an `Origin` outside it gets 403, a request with no `Origin` is allowed |

## Adding a relayed state

Pennsylvania was added 2026-09-22 and is the worked example. North Carolina is the one
left. Each needs its own token recipe found the way Florida's was (watch the agency's page
play a stream, copy the calls), a `mintToken` in `server.js`, a line in the `STATES` table
in `relay.js`, and a `relay` field on its index entry. Until then it is an honest snapshot
state.

Pennsylvania cost four small changes, and nothing in the streaming path:

- `relay.js` grew a `STATES` table keyed by the first path segment, so the path is now
  `/<state>/<imageId>/<seN>/<chan>/<file>` and the upstream origin is built per state.
- `server.js` grew `mintTokenPA`, which is Florida's dance minus the session: no cookie,
  no anti-forgery token, just `GetVideoUrl` and the vendor's token API.
- The token cache and the rate-limit backoff are keyed per state. One agency's 429 must
  not stall the other, and the same `imageId` is a different camera in each state.
- `videoFor()` in `index.html` matches both vendor hosts, not just divas.

**Find the recipe before assuming the relay is the answer.** Texas was on this list and did
not belong: its lock is a query-string token a browser can mint for itself, so it plays
direct with no relay at all, flagged `"sign": "tx"` instead of `"relay"`. See
[Texas](3.26-texas.md) and [decision 0014](6-decisions/0014-texas-signs-its-own-streams.md).
The relay is for a lock a page on another origin genuinely cannot reproduce, which means a
header like Florida's and Pennsylvania's `Referer`. A token alone is not that. The check is
two curls: mint a token by hand, then fetch the playlist with it and without the agency's
`Referer`. If it plays, the state does not need this.

## Files

- `relay/relay.js`: the path parser, upstream URL, playlist rewrite, origin check. Pure, tested.
- `relay/server.js`: the HTTP server, the session and token cache, the streaming pass-through.
- `relay/relay.test.js`, `relay/Dockerfile`, `relay/README.md`.
