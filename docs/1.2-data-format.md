# Data format

Every file the map reads is plain JSON committed to the repo. This page shows each shape
once, with a real example, so a builder can be written and a file can be checked by eye.

## states/index.json

One object keyed by state code. The map reads it at load to build the sidebar and the
coverage overview.

```json
"FL": {
  "name": "Florida",
  "file": "states/FL.json",
  "count": 4904,
  "center": [-81.7, 28.2],
  "zoom": 6,
  "video": true
}
```

| Field | Meaning |
|---|---|
| `count` | Camera locations (pins), not lenses. A pole with three views is one. |
| `video` | Whether the builder saw a sampled stream play from a browser-like request. See [Sources](3-sources.md) for the rule. |
| `imgproxy` | Optional. `"wsrv"` means the snapshot host is http-only and the page routes the image through an https proxy at render time. Only New Mexico today. |

## states/CODE.json

A GeoJSON FeatureCollection. One feature per camera location; each feature carries one or
more `directions`, which are the views at that location.

```json
{
  "type": "Feature",
  "geometry": { "type": "Point", "coordinates": [-122.33, 47.61] },
  "properties": {
    "name": "I-5 at Seneca St",
    "kind": "live",
    "roadway": "I-5",
    "county": "King",
    "directions": [
      { "snapshot": "https://images.wsdot.wa.gov/nw/005vc00118.jpg",
        "video": null,
        "facing": "Northbound",
        "refresh_sec": 120 }
    ]
  }
}
```

| Field | Meaning |
|---|---|
| `directions[].snapshot` | The agency's still image URL, stored as the agency publishes it. `null` when the state is video-only or the camera has no feed. |
| `directions[].video` | An HLS playlist URL, only when the stream is playable from a static page (no token, no DRM, no Referer lock). `null` otherwise, on purpose. |
| `directions[].label`, `facing`, `direction` | The view name. Builders have used all three names over time; the popup reads `label`, then `facing`, then `direction`. |
| `directions[].refresh_sec` | How often the image really changes, only where it was measured (Washington). |
| `properties.rwis` | Road-weather text for a weather station camera, shown as a chip. |
| A direction with both `snapshot` and `video` null | A location-only pin: the camera exists, the agency publishes no feed. The popup says "No live image at this camera". |

Every URL is stored as the agency serves it, including `http://` where that is all the
host offers, so the health sweep fingerprints the real bytes and the health file keys
match. The page decides at render time how to load it.

## states/health/CODE.json

Written by the sweep for every snapshot state. Cameras that are fine are simply absent.

```json
{
  "checked_at": "2026-09-19T15:56:17Z",
  "cameras": 629,
  "counts": { "placeholder": 52, "frozen": 3, "offline": 1 },
  "status": {
    "https://api.algotraffic.com/v4/Cameras/1185/snapshot.jpg": "placeholder"
  }
}
```

The key is the snapshot URL with bare-digit cache-busters stripped and named query
parameters kept, the same rule as `snapKey` in `index.html`, so a camera whose identity
lives in the query string (Wyoming's `?ref=`, Mississippi's `streamname=`) keeps a unique
key. `known-placeholders.json` in the same folder remembers every confirmed placeholder
fingerprint so a lone down camera is caught later. Video-only states (Texas, Delaware,
Maryland, Missouri, Oklahoma, West Virginia) have no health file: there is nothing to
fingerprint, and the browser judges the stream instead.

## states/WA-refresh.json

The measured refresh interval per Washington camera, keyed by WSDOT's camera id, written
by `scripts/measure-refresh-wa.py` and folded in by the Washington builder.

```json
{
  "measured_at": "2026-07-09T22:10:00Z",
  "window_sec": 840,
  "passes": 9,
  "cameras": { "9248": { "refresh_sec": 377, "changes": 2, "samples": 9 } }
}
```

`refresh_sec` is `null` for a camera that was not caught refreshing twice inside the
window; the builder then leaves the popup on the generic wording. See
[Refresh rate](4.1-refresh-rate.md).

## The city layers

`cameras.json` (Illinois) and `cameras-nyc.json` (New York City) predate the state files
and keep their own shape: the same feature and `directions` idea, with Illinois storing the
view name as `direction` and New York City storing a `camId` from which the page builds
the image URL. `cameras-chicago-enforcement.json` is not a camera feed at all; its shape is
described in [Chicago tickets](2.2-chicago-tickets.md).
