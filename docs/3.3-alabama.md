# Alabama

629 cameras from ALGO Traffic (algotraffic.com, ALDOT), snapshot-only, built by
`builders/build-states-al.py`. Alabama is the state that taught the builders to read the
chunklist: DRM behind a green CORS check.

## Where the list comes from

`GET https://api.algotraffic.com/v4.0/Cameras`, an open endpoint returning every camera
with coordinates, an HLS playlist, and a snapshot URL. Read 2026-07-12.

## How images and video are read

Snapshots are `https://api.algotraffic.com/v4/Cameras/<id>/snapshot.jpg`, https, no
referrer games, refreshed at the origin about every 10 minutes (`Cache-Control:
max-age=600`).

Video is refused on purpose. The Wowza CDN answers the playlist with
`Access-Control-Allow-Origin: *`, so a CORS probe alone would flag the state live, but
every chunklist carries `#EXT-X-KEY:METHOD=SAMPLE-AES` pointing at fps.ezdrm.com: FairPlay
DRM licensed per session. hls.js cannot decrypt it, no static page can, and algotraffic.com
itself defaults to the still and makes you flip a switch that boots a DRM player. All five
regional CDNs (tuscaloosa, mnt, bhm, mobile, tuscumbia) sampled DRM'd. Video URLs are
written as `null` so a future naive CORS check cannot resurrect them.

## What a camera gives us

Name, one view, a compass chip from the feed's direction field.

## Known limits

- Snapshot-only for as long as the streams stay DRM'd.
- [Decision 0003](6-decisions/0003-cors-alone-proves-nothing.md) records the rule this
  state produced: `video_plays()` in the newer builders reads the chunklist and refuses
  any stream that names a key.

## Runbook

From the repo root:

```bash
python3 builders/build-states-al.py
```

Expected: 629 cameras, `video: false`.
