# The 511 DataTables feed

Fifteen states run the older Castle Rock "511" platform and expose the same three
endpoints, so one builder reads them all: Florida, Georgia, Utah, Pennsylvania, North
Carolina, Nevada, Arizona, Wisconsin, Idaho, Maine, New Hampshire, Vermont, Connecticut,
Louisiana, and Alaska. Between them about 17,000 cameras. Video plays in Florida,
Pennsylvania, North Carolina, Nevada, Wisconsin, and Louisiana. New York left this
platform around 2026-09-30 and has [its own page](3.32-new-york.md).

## Where the list comes from

`https://<host>/List/GetData/Cameras` with a DataTables query in the URL: paged JSON with
the camera name, a `latLng` in WKT, image ids, and video URLs. The hosts are in `STATES`
in the builder (`fl511.com`, `511ga.org`, `udottraffic.utah.gov`, `www.511pa.com`,
`drivenc.gov`, `nvroads.com`, `az511.com`, `511wi.gov`, `511.idaho.gov`,
`www.newengland511.org`, `ctroads.org`, `511la.org`, `511.alaska.gov`).

`newengland511.org` serves Maine, New Hampshire, and Vermont from one list. A bounding box
cannot separate them cleanly, so the builder believes each row's own `state` column
(`only_state`).

## How images and video are read

The snapshot is `https://<host>/map/Cctv/<imageId>`, a JPEG the agency refreshes. Video is
the `videoUrl` on each image entry, an HLS playlist on some states. The builder samples up
to eight streams per state and refuses any URL carrying `token=`; Kansas and Massachusetts
are on the GraphQL platform, but the same rule applies here.

## What a camera gives us

Name, one or more views, the snapshot URL, the stream URL where it plays, and the feed's
`direction` column where present (Northbound, Southbound, or Both Directions), which
becomes the compass chip.

## Known limits

- **Florida's and Pennsylvania's streams are locked since September 2026.** Both hosts
  answer only with a per-camera token and the agency's own `Referer`, so the map plays both
  through the [stream relay](1.4-stream-relay.md); the stored URLs are unchanged. Florida is
  divas.cloud with a `Referer` of fl511.com, Pennsylvania is arcadis-ivds.com with a
  `Referer` of 511pa.com. The two are the same vendor platform, and each host rejects the
  other's `Referer`, so the relay sends the right one per state.
- **Pennsylvania's token needs no session**, unlike Florida's: no cookie and no
  anti-forgery token, just `GET www.511pa.com/Camera/GetVideoUrl?imageId=<id>` and a POST
  of that JSON to `pa.arcadis-ivds.com/api/SecureTokenUri/GetSecureTokenUriBySourceId`.
  Note that PennDOT's `sourceId` is a name (`mp10-5e-fortcherryroad`), not a number.
  Traced 2026-09-22.
- `Camera/GetUserCameras` returns rows whose `videoUrl` is sometimes populated and
  sometimes empty, because it answers per session. The empty result is what made
  Pennsylvania look like it had no stream URLs at all. The builder does not depend on it.
- North Carolina locked the same month on the same vendor ("XEngine" Basic auth, port
  8887) and is still a snapshot state until its recipe is traced.
- About 5 percent of any state's cameras are down at a given moment. Georgia's placeholder
  rate measured 25 percent, Alaska 27, Florida 13, Arizona 10.
- Georgia's video is 401 auth-gated, so Georgia is snapshot-only.
- Georgia and North Carolina answer a HEAD request with `Content-Length: 0`; the sweep
  uses a range GET for that reason.

## Runbook

From the repo root:

```bash
python3 builders/build-states.py            # every state in STATES
python3 builders/build-states.py GA CT      # just these
python3 builders/build-states-me-turnpike.py   # after ME: appends the Maine Turnpike sites
```

The builder merges into `states/index.json`; it never overwrites entries built by other
scripts (it once did, and deleted six states, which is why it merges now).
