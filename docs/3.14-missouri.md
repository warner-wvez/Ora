# Missouri

737 pins from MoDOT's Traveler Information Map, live video and no snapshots, built by
`builders/build-states-mo.py`.

## Where the list comes from

One static feed, `traveler.modot.org/timconfig/feed/desktop/StreamingCams2.json`, an
array of `{location, x, y, rtmp, html}` where `html` is the HLS playlist. Read
2026-07-11.

## How images and video are read

Video-only, like Texas: there is no still field, so the popup plays over a dark backdrop.
Two stream shapes, both CORS-open and both token-free as stored:

- About 560 direct Wowza edges, `sfs0N-traveler.modot.mo.gov/rtplive/<cam>/playlist.m3u8`
  and s2.ozarkstrafficoneview.com, with CORS `*` on playlist and segments.
- About 320 at `traveler.modot.org/tisvc/api/Tms/CameraStream/<code>`, which
  303-redirects to a streamlock.net playlist carrying a fresh Wowza token minted per
  request. The stored URL has no token, so it is legal under
  [decision 0002](6-decisions/0002-no-expiring-tokens.md): the rule forbids baking a
  credential in, not following a redirect that issues one at play time. The browser
  re-follows it on every open.

## What a camera gives us

Location name, one or more streams; cameras on one coordinate collapse into one pin with
a view each.

## Known limits

- **Kansas City is bi-state.** MoDOT's feed is the joint KC Scout system and carries the
  Kansas-side metro cameras (I-35, I-435, I-635, US-69, K-7, K-10), which Ora already has
  from kandrive.gov. A bounding box cannot cut them because Platte County juts west of the
  state-line meridian along I-29, so the builder rejects by a point-in-Missouri test
  against `states-outline.json`, scoped to the western border (longitude below -94) so the
  coarse outline cannot nick a Mississippi-riverfront camera on the far side. 142 dropped.
- No health file; the browser judges the streams.

## Runbook

From the repo root:

```bash
python3 builders/build-states-mo.py
```

Expected: 737 pins, `video: true`.
