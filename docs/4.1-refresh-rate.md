# Refresh rate

Most agencies publish a camera's name and a URL and nothing about how often the picture
changes. Washington's popup states a refresh rate per camera; no other state's does, and
this page says why both halves of that are true.

## Why it had to be measured

WSDOT publishes no refresh field anywhere: not in the REST API, not in the map's
`appconfig.json`, not on the cameras page. Every JPEG does carry a `Last-Modified` header.
`scripts/measure-refresh-wa.py` polls HEAD on a cadence, watches that timestamp move, and
writes `states/WA-refresh.json`, which the Washington builder folds into each view as
`refresh_sec`. Ages are computed against the server's own `Date` header, so a skewed clock
(a couple of these images live on a ski lodge and a Park Service host) can corrupt only
itself.

## Two estimators

Either one alone fails predictably, and their failures do not overlap.

- `window / changes` is right for cameras slower than the polling cadence and overestimates
  faster ones, because refreshes slip between passes.
- `max(observed age) * (n+1)/n` cannot be fooled by that aliasing, since an image's age at
  a random moment is roughly uniform on `[0, T]`; it is weak only when `T` approaches the
  run length.

Both err upward, so the build takes the smaller. A camera has to be caught refreshing
**twice** to get a number. With one refresh the estimator just echoes the run length back:
it once labelled 85 cameras "about 14 minutes" on a 14-minute run.

## What it found

Measured 2026-07-09: median 2 minutes, 232 cameras at about a minute, the slowest rated one
at 7 minutes. 143 cameras refresh slower than the 14-minute run could pin down and fall
back to the generic wording. 11 cameras return `IsActive: true` while serving an image
unchanged for over a day, and four ferry cameras have served the same bytes since
September 2003; those get an amber "no new image since" instead of a rate and stop being
polled every 30 seconds.

The popup polls at the measured rate instead of a flat 30 seconds, which stops it
re-fetching an identical JPEG twenty times.

## Why only Washington

Other feeds carry a single `updateTime` or none. One "how old is this image now" sample is
biased low and would over-claim, so South Dakota's synthesized cadence was removed the day
it shipped and no other state states a number. The same measurement is a dead end for
"meshing" snapshots into video: snapshot-only agencies refresh every one to two minutes at
best, so polling faster only re-fetches identical frames.
[Decision 0008](6-decisions/0008-no-snapshot-meshing.md).

## Runbook

```bash
WSDOT_API_KEY=your-key python3 scripts/measure-refresh-wa.py 9 90   # 9 passes, 90 s apart
WSDOT_API_KEY=your-key python3 builders/build-states-wa.py
```

Run from the repo root. The first command takes about 14 minutes.
